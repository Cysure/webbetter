Core Web Vitals 2026: Geschwindigkeit entscheidet noch immer über Rankings

Der stille Zinseszins einer schnellen Website: bessere Rankings, günstigere Anzeigen, mehr Conversions. Eine praktische Checkliste aus unseren Relaunches.

ENGINEERINGVeröffentlicht 28. SEPTEMBER 2026

Das Wichtigste in Kürze

  • Gut heisst: LCP innerhalb von 2,5 Sekunden, INP von höchstens 200 Millisekunden und CLS von höchstens 0,1, gemessen am 75. Perzentil echter Besuche.
  • Laut Google entsprechen gute Core Web Vitals dem, was die Ranking-Systeme belohnen. Relevanz kommt weiterhin zuerst, Geschwindigkeit ist ein Tiebreaker, den man nicht verlieren sollte.
  • Der Business Case ist gemessen: Im A/B-Test von Vodafone brachte ein 31 % schnellerer LCP 8 % mehr Verkäufe.

Alle paar Jahre erklärt jemand, die Ladezeit spiele für SEO keine Rolle mehr. Alle paar Jahre zeigen die Daten das Gegenteil. Geschwindigkeit war nie das stärkste Ranking-Signal und ist es auch heute nicht. Aber sie beeinflusst alles, was nach dem Ranking kommt: ob der Besuch bleibt, ob das Formular ausgefüllt wird, ob der bezahlte Anzeigenklick zur Kundin wird.

Die drei Zahlen

Google misst die Nutzererfahrung mit drei Core Web Vitals. Jede hat einen klaren Grenzwert für «gut».

2,5 sLargest Contentful Paint: wann der Hauptinhalt erscheint
200 msInteraction to Next Paint: wie schnell die Seite reagiert
0,1Cumulative Layout Shift: wie stark das Layout springt

Zwei Details werden oft übersehen. Erstens gelten die Grenzwerte für das 75. Perzentil der Seitenaufrufe, getrennt nach Mobile und Desktop. Ein schneller Test auf dem Büro-Laptop beweist wenig. Drei von vier echten Besuchen, auf echten Smartphones und in echten Netzen, müssen gut sein. Zweitens hat INP den First Input Delay im März 2024 als Core Web Vital abgelöst. FID mass nur die Verzögerung vor der ersten Interaktion. INP bewertet die Reaktionsfähigkeit über den ganzen Besuch, was sich kaum schönrechnen lässt und viel näher daran ist, wie sich eine langsame Website anfühlt.

Was Google tatsächlich über Rankings sagt

In der Dokumentation der Google-Suche heisst es, gute Core Web Vitals entsprächen dem, was die zentralen Ranking-Systeme belohnen wollen, und Google empfiehlt sie für den Erfolg in der Suche. Google verspricht nicht, dass schnelle Seiten relevante Seiten überholen, und niemand sollte das behaupten. Eine langsame Seite mit der besten Antwort schlägt meist eine schnelle Seite mit einer schwachen.

In der Praxis wirkt Geschwindigkeit als Tiebreaker zwischen ähnlich relevanten Seiten. In umkämpften Märkten ist genau das Ihre Lage: mehrere Agenturen, Shops oder Praxen mit ähnlichem Angebot und vergleichbaren Inhalten. Diesen Tiebreaker zu verlieren, lässt sich vermeiden.

Was Geschwindigkeit wert ist

Das stärkere Argument für Geschwindigkeit ist kommerziell, und hier ist die Beweislage besser als die Folklore.

  • Vodafone führte einen A/B-Test auf einer Landingpage durch, die sich nur in der Performance unterschied. Die optimierte Version hatte einen um 31 % besseren LCP und brachte 8 % mehr Verkäufe, eine um 15 % bessere Lead-to-Visit-Rate und eine um 11 % bessere Cart-to-Visit-Rate.
  • Deloitte stellte in einer von Google beauftragten Studie fest, dass eine um 0,1 Sekunden schnellere mobile Website über die ganze Customer Journey die Conversions im Detailhandel um 8,4 % und im Reisebereich um 10,1 % steigerte. Im Detailhandel gaben Kundinnen und Kunden pro Bestellung zudem 9,2 % mehr aus.

Diese Gewinne verstärken sich. Eine schnellere Seite konvertiert mehr vom bestehenden Traffic, das senkt die Kosten pro Lead aus Anzeigen, und mit demselben Budget lässt sich mehr Traffic kaufen. Geschwindigkeit gehört zu den wenigen Verbesserungen, die sich gleichzeitig in SEO, bezahlten Medien und Conversion auszahlen.

Das Richtige messen

Labor-Tools wie Lighthouse helfen bei der Fehlersuche, simulieren aber einen einzigen Besuch auf einem Gerät. Google bewertet Ihre Seiten mit Felddaten echter Chrome-Nutzer, gesammelt im Chrome UX Report und sichtbar im Core-Web-Vitals-Bericht der Search Console. Optimieren Sie, bis die Felddaten grün sind. Ein perfekter Lighthouse-Score mit schlechten Felddaten ist immer noch eine schlechte Website.

Unsere Checkliste für jeden Relaunch

  1. LCP: das Hero-Bild in einem modernen Format und in passender Grösse ausliefern, nie lazy laden und mit Fetch-Priorität versehen. Die wichtigste Webschrift vorladen oder eine Systemschrift verwenden.
  2. LCP: den Hauptinhalt als HTML vom Server oder vom Edge rendern. Wer mit der Überschrift auf ein JavaScript-Bundle wartet, verliert auf Mittelklasse-Smartphones Sekunden.
  3. INP: weniger JavaScript ausliefern. Ungenutzte Bibliotheken entfernen, Code pro Route aufteilen und Skripte von Drittanbietern erst laden, wenn sie gebraucht werden.
  4. INP: Event-Handler kurz halten. Lange Aufgaben aufteilen, damit der Browser dazwischen zeichnen kann, und sofort Feedback zeigen.
  5. CLS: für jedes Bild, Video, Embed und jede Anzeige Platz reservieren, mit width und height oder aspect-ratio. Nie nach dem Laden Banner über dem Inhalt einfügen.
  6. Alles: Tag Manager und Chat-Widgets jedes Quartal prüfen. Bei den meisten Websites, die wir analysieren, sind Skripte von Drittanbietern der grösste einzelne Kostenpunkt.

Wir halten uns selbst daran: webbetter.ch zeigt im Footer jeder Seite den eigenen Largest Contentful Paint, Layout Shift und die Reaktionszeit live an, gemessen in Ihrem Browser, während Sie lesen.

Geschwindigkeit schafft es selten auf die Titelfolie einer Strategie. Sie ist weniger sichtbar als eine neue Marke und weniger aufregend als die KI-Suche. Aber sie entscheidet still darüber, wie viel von allem anderen sich tatsächlich auszahlt.
